## What improves

- **Cold builds work on Ubuntu 26.04 hosts, this time all the way.** v0.20261103.1 got 26.04 builds past making the install media, and then the guest stopped at its first firmware instruction: Ubuntu 26.04's gcc compiles for newer CPUs than the guest's by default, and the firmware the plugin builds (OpenCore and OVMF) inherited that, so the guest faulted before macOS started and the build ended an hour later with "Timeout waiting for SSH". The firmware is now always compiled for plain x86-64, the CPU every guest model offers.
- **A firmware build that would not run in the guest now fails instead.** After building, the plugin checks every firmware module it ships and refuses the build, naming the module, the instruction and its source line, if the compiler used anything newer than x86-64. Before, such firmware was shipped and the guest hung at boot.

## Upgrading

- On a host whose gcc already compiled for plain x86-64 (Ubuntu 24.04, Debian 13, Arch, and every host this project had tested), the firmware is byte-for-byte the same as before. Its build inputs did change, so the next build of each guest starts cold, once.
- The firmware build now needs `objdump`. It comes with binutils, which gcc already brings; the build names it if it is missing.

## Known limits

- About 2% of cold Mavericks builds on GitHub's AMD EPYC 7763 runners stall partway through the install, and the build ends with "Timeout waiting for SSH". The cause is not yet known; `docs/decisions/0040` describes what is read when it happens.
- If you build in a directory your group can write to, a member of that group could replace the QEMU monitor socket's directory just before QEMU starts and so take control of the guest being built. The plugin allows group-writable directories because a umask of 002 makes them common.

Images and boxes contain Apple's operating system. **Never publish them.**
