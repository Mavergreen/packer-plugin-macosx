## What improves

- **Snow Leopard guests get a correct memory map.** OpenCore could hand the 10.6 kernel a memory map with one extra entry, a copy of memory it had already listed, whenever the map's last entries had been merged. A 4 GiB guest's map takes that shape. Two entries claiming the same memory is the kind of fault that turns up later as a panic or corrupted memory that seems to come from nowhere. The plugin now builds OpenCore with the one-line fix. Mavericks never ran that code.
- **A guest whose boot files fragment still boots.** OpenCore's HFS+ driver could not read a file stored in more than eight pieces: it read the first eight and then failed. Fresh builds keep the kernel and its caches in one or two pieces, so they were never affected. A box used for a long time, whose disk fills up and then rebuilds its kernel cache, could stop booting. The driver now reads such files whole, and one of its searches can no longer read past the data it was given.

## Upgrading

- The firmware's build inputs changed, so the next build of each guest starts cold, once.

## Known limits

- About 2% of cold Mavericks builds on GitHub's AMD EPYC 7763 runners stall partway through the install, and the build ends with "Timeout waiting for SSH". The cause is not yet known; `docs/decisions/0040` describes what is read when it happens.
- If you build in a directory your group can write to, a member of that group could replace the QEMU monitor socket's directory just before QEMU starts and so take control of the guest being built. The plugin allows group-writable directories because a umask of 002 makes them common.

Images and boxes contain Apple's operating system. **Never publish them.**
