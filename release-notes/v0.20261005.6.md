Snow Leopard guests now boot every time. Before, a 10.6 guest under KVM
often sat at its login window without logging in, and never answered SSH:
`vagrant up` timed out, and a 10.6 build could time out on its second boot.

The cause was the guest's clock chip. QEMU tells the guest it has more of
the clock's memory than it really does, and Mac OS X reads the missing part
as a record that sleep failed in every possible way. 10.6's network
configuration daemon crashes on that record, over and over, so the guest
never brings its network up. The firmware now describes the clock as QEMU
actually provides it.

Mavericks guests booted either way, but reported the same false sleep
failure on every boot; they no longer do.

The firmware changes, so the next build rebuilds its EFI image, and the
next guest you build gets the fix. A box built before this release keeps
the old firmware: rebuild it to stop the hangs. `docs/decisions/0015` has
the measurements.

One 10.6 build in three still failed, for a different reason: when the
build restarted the guest after installing the 10.6.8 update, the guest
never actually restarted. That one is still being investigated.

Mavericks guests can now reach github.com and GitHub's release downloads
over HTTPS. A stock 10.9.5 guest's `curl` fails on both with "Invalid
certificate chain": it lacks the root certificates their chains end in
(downloads.claude.ai works without it). A new
template, `mavericks-aquatransport`, builds a box over the Mavericks box
you've already built, with Wowfunhappy's Aqua Transport and its modern root
certificates installed, and without its AirDrop kernel extension. It takes
about six minutes, not a full Mavericks build. It restarts the guest and
checks it, and makes no box unless the system's own `curl` reaches
github.com, GitHub's release downloads and downloads.claude.ai. The README's
"Mavericks with Aqua Transport" has the commands.

Aqua Transport is downloaded at build time from Mavericks Forever, and never
shipped here. The build accepts only the version this release pins, and the
download is replaced in place with each new version. So once Aqua Transport
moves on, this release can no longer build the layer, and says so, naming
both checksums; a later release pins the new one. `docs/decisions/0016` has
the measurements.

Each release now also carries a base recipe,
`packer-plugin-macosx_<tag>_mavericks_base_recipe.txt`: a checksum of what
the Mavericks image is built from. It stays the same from a release to the
next unless the base image's sources change, so a release that only moves
the layer leaves a cached base image good.

The image, and any box made from it, contain Apple's operating system. Never
publish either one.
